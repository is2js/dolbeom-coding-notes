# 돌범의 코딩 작업실

**돌범이 풀어주는 AI 구독 전 코딩 필수 노하우** — Codex로 코딩해 봤지만 기초 개발 도구가 낯선 사람을 위한 7강 강의노트입니다.

[강의 주소](https://is2js.github.io/dolbeom-coding-notes/#/lesson/terminal/case) · [발표 모드](https://is2js.github.io/dolbeom-coding-notes/#/present/terminal/case) · [원본 저장소](https://github.com/is2js/dolbeom-coding-notes)

**실제 화면은 이미 Alpine.js와 Tailwind CSS로 구현되어 있습니다.** Vite는 로컬 개발 서버를 실행하고 배포할 정적 파일을 만드는 도구입니다. GitHub Pages는 빌드된 HTML·CSS·JavaScript·JSON을 제공하므로, 게시된 사이트에 Vite 서버나 Node.js 프로세스를 실행할 필요가 없습니다.

로컬의 `npm run dev`에서는 **웹 편집기와 `public/data/course.json`이 자동으로 서로 반영됩니다.** GitHub Pages와 정적 미리보기의 편집 내용은 **현재 브라우저에만 저장**되며, 공개 강의 갱신에는 JSON 반영과 재배포가 필요합니다.

| 순서 | 할 일 | 명령·위치 |
| --- | --- | --- |
| 1. 준비·로컬 수정 | 처음에 의존성을 준비하고 웹 편집기나 Codex로 수정합니다. | 처음 또는 `package-lock.json`의 의존성이 바뀐 뒤 `npm ci` → `npm run dev` → **http://127.0.0.1:5188** |
| 2. 검증·빌드 | 저장된 원본을 검사해 `dist/`를 만듭니다. | `npm test` → `npm run check:content` → `npm run build` → `npm run check:dist` |
| 3. 정적 미리보기 | 배포될 화면을 확인합니다. 여기서 편집하면 브라우저에만 저장됩니다. | 빌드 후 `npm run preview` → **http://127.0.0.1:4188** |
| 4. 수동 게시 | 검증한 내용을 공개 저장소에 반영하고 수동 게시합니다. | 커밋·push → **Actions → Deploy GitHub Pages → Run workflow** |

공개 저장소 연결과 GitHub Pages의 수동 배포 설정을 마쳤습니다. 사이트 내용은 **Deploy GitHub Pages** 실행 결과에 따라 반영됩니다. 갱신 순서는 아래 [GitHub Pages 수동 배포](#github-pages-수동-배포)를 따릅니다.

2026-10-26 개요에 맞춘 **7개 주제 · 본편 22개 절 · 180분** 초안입니다. 주제별 흐름, 바로잡은 개념, 다음 내용을 전달하는 방법은 [강의 흐름과 수정 안내](LECTURE_FLOW.md)에 정리했습니다.

## 강의처럼 진행하면서 수정하기

1. [강의 연습 열기](http://127.0.0.1:5188/#/lesson/terminal/case)에서 주제를 고릅니다. **시작 사례 → 본문 절 → 핵심 정리** 순서로 진행합니다.
2. **왼쪽은 현재 설명 위치, 가운데는 그 절의 그림·예제, 오른쪽은 설명할 본문**입니다. **다음 설명**을 누르면 세 영역이 함께 바뀝니다. 좁은 화면에서는 위의 **현재 설명할 부분** 선택 메뉴를 사용합니다.
3. 본문의 **이 내용 수정**을 누르고 고친 뒤 **이 내용으로 연습**을 누릅니다. 저장을 확인한 다음 같은 절로 돌아와 이어갑니다.

기본 본문 22개 절은 서로 다른 SVG 장면을 사용합니다. **관련 예제 재현**에는 현재 절에 연결된 시연만 표시됩니다. 명령을 실제 실행하는 기능은 아니며 실전은 강사의 도구에서 진행합니다.

[본문 편집만 열기](http://127.0.0.1:5188/#/editor/terminal/terminal-example)에서는 왼쪽에서 입력하고 오른쪽에서 바로 확인할 수 있습니다. 발표 요약·순서·시연·JSON은 **상세 설정**에 있습니다.

## 로컬 실행

**Node.js 20.x의 20.19 이상, 22.x의 22.12 이상 또는 24.x와 npm**을 사용합니다. 자동 검증·배포 워크플로는 **Node.js 24.x**를 사용합니다. Windows PowerShell에서 실행합니다.

```powershell
cd C:\work\dolbeom-coding-notes
npm ci
npm run dev
```

`cd`의 경로는 실제 프로젝트 폴더로 바꿉니다. `npm ci`는 처음 준비하거나 `package-lock.json`의 의존성이 바뀌었을 때 실행합니다. 강의 원고·화면만 수정할 때는 매번 설치하지 않고 `npm run dev`로 시작합니다.

브라우저에서 **http://127.0.0.1:5188** 을 엽니다. HTML 파일을 직접 더블클릭하는 대신 개발 서버를 사용하세요.

| 실행 방식 | 주소 | 웹 편집기 저장 위치 | 프로젝트 파일 자동 반영 |
| --- | --- | --- | --- |
| `npm run dev` | `http://127.0.0.1:5188` | 현재 브라우저 초안 + 로컬 강의 파일 | 지원 |
| `npm run preview` | `http://127.0.0.1:4188` | 현재 브라우저 | 미지원 |
| GitHub Pages | [is2js.github.io/dolbeom-coding-notes](https://is2js.github.io/dolbeom-coding-notes/) | 현재 브라우저 | 미지원 |

검증·빌드 명령은 아래 [180분 커리큘럼과 확인 명령](#180분-커리큘럼과-확인-명령)에 있습니다. 빌드 결과는 `dist/`이며, 정적 미리보기는 빌드 후 실행합니다.

## 웹 편집기와 Codex를 함께 쓰기

| 자주 바꾸는 내용 | 편집 위치 |
| --- | --- |
| 전체 강의 제목·작성자 | **상세 설정 → 01 강의 정보 → 전체 강의 제목과 작성자 수정**을 펼칩니다. |
| 주제 제목 | 목차에서 강의 선택 → **상세 설정 → 01 강의 정보**의 **강의 제목**, **메뉴에 표시할 짧은 제목**을 수정합니다. |
| 주제 순서 | **상세 설정**의 강의 목차에서 **↑ / ↓**를 누릅니다. 번호는 자동으로 정리됩니다. |
| 강의 본문 | **본문 편집**에서 강의와 절을 선택합니다. 왼쪽 입력과 오른쪽 미리보기가 함께 보입니다. |

1. 왼쪽 톱니바퀴 또는 하단 **강의 편집**을 누릅니다 (`#/editor`).
2. 기본 **본문 편집**에서 도입 사례나 본문 한 절을 고릅니다. 왼쪽에서 고치면 오른쪽 미리보기에 즉시 표시됩니다. 발표·시연·정리 자료와 순서 변경은 **상세 설정**에서 수정합니다.
3. 실제 개발 경험을 입력한 뒤 **상세 설정 → 01 강의 정보**에서 사례 구분을 **실제 경험**으로 바꿉니다. 초기 콘텐츠의 사례는 교체용 가상 예시입니다.
4. 입력은 현재 브라우저의 편집 초안에 즉시 저장됩니다. 유효한 변경은 입력을 멈춘 뒤 **650ms 후 `public/data/course.json`에도 자동 저장**됩니다. 편집기 저장 상태에 **파일 저장 완료**가 표시되는지 확인합니다.
5. 파일 저장 완료를 확인한 뒤 Codex에게 추가로 고칠 내용을 요청합니다. Codex는 **현재 `public/data/course.json`을 먼저 읽고** 수정합니다. 브라우저는 파일 변경을 감지해 새로고침 없이 반영합니다.

Codex에게 “저장했어”라고 따로 알릴 필요는 없습니다. 실제로 원하는 수정만 요청하면 됩니다.

> `public/data/course.json`의 최신 내용을 읽고, 3강의 첫 사례를 제 설명에 맞게 다듬어 주세요. 강의 ID와 기존 시연은 유지하고 본편 총시간 180분을 확인해 주세요.

개발 서버가 실행 중이고 페이지가 보이는 동안 파일 변경을 **2초 간격**으로 확인하며, 페이지로 다시 돌아왔을 때도 확인합니다. 브라우저에 아직 파일로 반영하지 못한 편집이 없으면 Codex나 텍스트 편집기가 바꾼 파일을 자동으로 불러옵니다.

본문 절과 시연 단계도 **상세 설정**에서 순서를 바꿀 수 있습니다. 변경한 제목과 주제 순서는 수강생 화면의 목차에 함께 반영됩니다. 표시 번호는 순서에 맞춰 정리되므로, 제목이나 순서를 바꾸기 위해 ID를 수정하지 마세요.

### 입력 오류·연결 끊김·동시 수정

- **입력 오류:** 제목을 잠깐 비우거나 시간을 수정하는 중처럼 유효하지 않은 입력도 브라우저 초안에 남습니다. 오류가 있는 상태는 강의 파일에 쓰지 않으며, 학습 화면에는 마지막 유효한 콘텐츠를 유지합니다. 오류를 고치면 자동 저장을 다시 진행합니다.
- **개발 서버 연결 끊김:** 브라우저 초안을 유지합니다. `npm run dev`를 다시 실행하고 편집기의 **파일 연결 다시 시도**를 누릅니다. 파일 저장 완료가 표시되기 전에는 브라우저 초안과 프로젝트 파일이 다를 수 있습니다.
- **브라우저와 파일을 동시에 수정:** 자동으로 한쪽을 덮어쓰지 않고 아래 두 선택지를 표시합니다. 새로고침 후 초안을 복원할 때도 그사이 파일이 바뀌었다면 먼저 선택합니다. 파일이 바뀌지 않았다면 보관한 초안을 이어서 편집할 수 있습니다.

| 충돌 선택지 | 적용 결과 |
| --- | --- |
| **최신 프로젝트 파일 불러오기** | 그 시점의 최신 파일 내용으로 브라우저 편집 내용을 바꿉니다. 프로젝트 파일은 변경하지 않습니다. 보존할 브라우저 내용이 있으면 선택 전에 JSON으로 내보내세요. |
| **내 편집본을 최신 파일에 저장** | 브라우저 편집본이 유효할 때 프로젝트 파일을 이 내용으로 바꿉니다. 기존 파일은 로컬 백업으로 보존합니다. |

**내 편집본을 최신 파일에 저장**을 선택하기 전에 파일이 또 바뀌었다면 덮어쓰지 않고 충돌을 다시 알립니다. 두 선택지는 자동 병합 기능이 아니므로, 양쪽 수정이 모두 필요하면 내용을 비교한 뒤 필요한 부분을 합쳐 저장합니다. JSON 내보내기에 입력 오류가 표시되면 먼저 오류를 고쳐 주세요.

웹 편집기가 프로젝트 파일을 저장하기 전의 내용은 **`.course-backups/`에 최근 30개**를 보관합니다. 이 폴더는 Git에서 제외합니다. 되돌릴 때는 필요한 백업의 내용을 확인한 뒤 `public/data/course.json`에 반영하세요. 브라우저에서는 이를 외부 파일 변경으로 감지합니다. Codex나 텍스트 편집기에서 파일을 직접 바꾼 순간에는 이 자동 백업이 생성되지 않습니다.

### 브라우저 저장과 JSON 백업

브라우저 초안은 현재 브라우저·주소에 저장됩니다. `localhost`와 `127.0.0.1`, 개발 포트와 미리보기 포트, 배포 사이트는 서로 다른 저장 공간입니다. 학습 완료 표시와 최근 위치는 강의 편집본과 별도로 저장합니다.

**상세 설정 → JSON 내보내기**는 전체 강의를 백업하거나 다른 기기·사이트로 옮길 때 사용합니다. 같은 곳의 **JSON 가져오기**는 내보낸 강의를 불러옵니다. 로컬 개발 중에는 원본 파일에 자동 저장되므로 매번 내보내고 가져올 필요가 없습니다. 잘못된 JSON은 오류를 표시하고 기존 편집 내용을 보존합니다. 브라우저 데이터를 지우기 전에는 필요한 강의를 내보내세요.

JSON을 가져오거나 파일 버전을 불러오는 동안에는 입력을 잠시 비활성화해 처리 중인 내용과 새 입력이 섞이지 않게 합니다. 브라우저 저장 공간이 부족해도 입력 내용이 유효하면 **JSON 내보내기**로 백업할 수 있습니다.

기존 6강에서 7강으로 바뀌면서 브라우저 편집본은 새 저장 키를 사용합니다. 이전 브라우저 데이터는 삭제하지 않습니다. 저장되지 않은 6강 초안이나 배포 사이트의 기존 편집본이 있으면 편집기에 **이전 6강 초안 JSON 받기**가 표시됩니다. 이 백업은 이전 형식을 그대로 보존하므로, 필요한 설명을 확인해 새 7강의 해당 항목에 옮겨 주세요. 새 7강 전체 가져오기에는 현재 7개 주제의 JSON을 사용합니다.

## GitHub Pages와 미리보기에서 편집하기

**4188 미리보기와 GitHub Pages의 편집은 브라우저 저장만 지원**합니다. 빌드된 정적 사이트에는 로컬 파일 동기화 서버가 없으므로 다른 기기의 공개 강의를 바꾸려면 다음 절차로 원본을 갱신합니다.

공개 강의를 갱신할 때는 다음 순서를 사용합니다.

1. 편집기에서 **JSON 내보내기**로 전체 강의를 받습니다.
2. 로컬 개발 서버의 편집기에서 **JSON 가져오기**를 사용하고 파일 저장 상태를 확인합니다. 또는 내보낸 JSON을 `public/data/course.json`으로 복사합니다.
3. 아래 검증을 실행합니다.
4. 변경 파일을 검토해 커밋·push한 뒤 **Deploy GitHub Pages**를 수동 실행합니다.

로컬 편집기에 동시 수정 안내가 보이면 사용할 버전을 먼저 선택한 뒤 JSON을 가져옵니다. 로컬 자동 저장은 Git 커밋·push·사이트 배포를 실행하지 않습니다.

## Zoom 녹화용 발표 모드

일반 강의 화면의 **발표 시작**을 누릅니다. 현재 탭에 진행 기록이 있으면 **발표 계속**으로 이어 갑니다. 주소는 `#/present/<강의ID>/<page>` 형식이며, 예를 들어 `#/present/git/case`는 Git의 시작 사례입니다.

발표는 **사례 → 본편 절별 핵심 요점 → 실전 예고 → 실전 진행 → 복귀 정리**로 이어집니다. 본편 22개 절을 순서대로 다루며 기본 발표 자료는 절마다 핵심 요점 3개를 보여 줍니다. 자세한 설명과 선택 보충은 **본문 보기**에서 확인합니다.

| 원하는 위치로 이동 | 상단에서 강의를 선택하고 하단에서 해당 강의의 단계를 선택합니다. |
| 전체화면 | 선택해서 켤 수 있습니다. **Esc는 전체화면만 해제**하므로 발표를 끝내려면 **발표 종료**를 누릅니다. |
| 원래 설명 읽기 | **본문 보기**로 현재 절의 원문을 대화상자에서 엽니다. 발표 요약을 위해 원문을 삭제하지 않습니다. |
| 대체 시연 | **준비된 재현 보기**로 현재 강의의 시연 단계와 재현을 확인합니다. 미리 작성된 코드·출력이며 실제 명령 실행이나 외부 프로그램 연결은 아닙니다. |
| 실전 타이머 | **멈춤 / 계속 / 처음부터**로 조절합니다. **처음부터**는 시간을 초기화한 뒤 정지하므로 필요할 때 다시 시작합니다. |
| 발표 마치기 | **발표 종료**를 누르면 현재 강의의 일반 학습 화면으로 돌아갑니다. |

실전 예고에서 프로그램·파일·명령·예상 결과를 읽고 **시연 시작**을 누릅니다. 강사가 **Alt+Tab으로 직접 IDE나 터미널에 전환**해 진행한 뒤 브라우저로 돌아와 **시연 끝내고 정리**를 누릅니다. 실제 결과를 확인하고 복귀 요약과 연결하세요.

현재 위치와 강의별 시연 시간은 **현재 탭의 세션 저장소**에 보관합니다. 같은 탭을 일반 새로고침하면 복원하며, 새 탭·새 세션은 별도 진행으로 사용합니다. 강의 콘텐츠 자동 저장과 발표 진행 기록은 서로 다른 저장 항목입니다.

### 발표 자료 편집

편집기의 **상세 설정 → 05 발표**에서 사례 요약, 본문 절별 핵심 요점, 시연 프로그램·파일·명령·예상 결과·시간, 복귀 요약을 수정합니다. **발표 미리보기 ↗**로 결과를 확인할 수 있으며 저장 중이거나 입력 오류가 있으면 마지막으로 적용된 강의를 보여 줍니다.

발표 정보가 없는 기존 JSON도 정상적으로 열리고 기존 사례와 본문을 사용합니다. 편집기에서 **발표 정보 준비**를 눌렀을 때만 현재 내용을 바탕으로 편집 초기값을 만듭니다. 요점을 삭제한 본편 절은 발표에서 본문으로 표시하며, 보충 절은 **본문 보기**에서 확인합니다.

발표 자료에도 앞에서 설명한 **650ms 자동 저장·로컬 파일 동기화**가 적용됩니다. Pages나 정적 미리보기에서는 브라우저 저장과 JSON 이동을 사용하며, 공개 강의 갱신은 기존 수동 배포 절차를 따릅니다.

### 녹화 전 준비

- 기본 실전 배정은 강의 순서대로 **3·4·3·2·3·4·6분, 합계 25분**입니다. 이 시간은 **전체 180분 안에 포함**하며 추가하지 않습니다.
- 브라우저와 IDE의 글자를 녹화에서 읽을 크기로 키우고, 같은 프로젝트의 시작 상태·완료 상태를 미리 준비합니다.
- 별도의 실습 프로젝트는 제공하지 않습니다. 실제 Git 저장소·원격 PR·Python/Jinja 실행 환경은 강사가 준비하고, 준비하지 못한 부분이나 인증·네트워크 실패는 **준비된 재현 보기**로 설명합니다.
- Alt+Tab 전환까지 함께 보이려면 Zoom에서 브라우저 한 창 대신 **발표용 모니터의 전체 화면**을 공유하고 Zoom의 녹화를 시작합니다. 브라우저의 전체화면 설정과 Zoom의 공유 대상은 별개입니다. [Zoom 공식 화면 공유 안내](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0059642)는 전체 데스크톱을 공유하면 앱과 파일을 여는 화면도 함께 보인다고 설명합니다.

## 180분 커리큘럼과 확인 명령

| 기본 순서 | 강의 | 본편 |
| --- | --- | ---: |
| 1 | 윈도우 터미널 | 25분 |
| 2 | Git | 25분 |
| 3 | GitHub | 20분 |
| 4 | 마크다운 | 20분 |
| 5 | IDE | 20분 |
| 6 | 프론트엔드·백엔드 | 25분 |
| 7 | 템플릿 | 45분 |

각 강의는 Codex를 사용하다 만난 사례로 시작합니다. 프론트엔드·백엔드 강의에서는 React·Svelte와 FastAPI·Spring을 역할 중심으로 비교합니다. 템플릿 강의에서는 Jinja2·Django 템플릿의 차이를 살펴보고, 같은 HTML 카드에 CSS와 JavaScript를 차례로 적용한 뒤 Tailwind CSS·Alpine.js로 연결합니다.

절별 예상 시간에는 사례 소개·설명·시연·정리가 포함됩니다. 보충 절은 별도로 집계합니다. 편집기에서 본편 합계와 보충 시간을 확인하고, 시간이나 본편·보충 구분을 바꾼 뒤에는 본편 합계를 180분으로 맞춥니다. 예상 분량은 강사가 촬영·편집할 때 참고하는 값이며 영상·음성 파일은 포함하지 않습니다.

현재 본문은 오른쪽에 항상 보이며 **본문 크게 읽기**에서 확대합니다. 왼쪽 설명 순서나 **다음 설명**으로 본문·그림·관련 예제를 함께 이동합니다. 시연은 사전 작성된 코드·출력·화면 상태이며 실제 명령 실행이나 실제 IDE 연결 기능은 없습니다. 참고 사이트의 3D 조작 대신 SVG 기반 입체 도구 지도와 클릭 가능한 설명을 제공합니다.

콘텐츠나 코드를 수정한 뒤 PowerShell에서 확인합니다.

```powershell
npm test
npm run check:content
npm run build
npm run check:dist
```

`check:content`는 **현재 `public/data/course.json`**의 구조와 본편 180분을 검사합니다. `check:dist`는 빌드된 파일과 배포 경로를 확인하므로 build 다음에 실행합니다. 브라우저에서는 수정한 강의·순서·시연·노트 확대와 실제 저장 상태를 확인합니다. 로컬에서 파일 저장이 완료되어야 다음 빌드에도 그 내용이 들어갑니다.

## GitHub Pages 수동 배포

소스 저장소 [is2js/dolbeom-coding-notes](https://github.com/is2js/dolbeom-coding-notes)는 **공개 상태**이며, Pages 게시 소스는 **GitHub Actions**로 설정되어 있습니다. 게시 주소는 **https://is2js.github.io/dolbeom-coding-notes/** 입니다. 프로젝트와 `.github/workflows/`는 저장소 루트에서 관리합니다.

- `.github/workflows/checks.yml`: 모든 브랜치의 push와 pull request에서 테스트·콘텐츠·빌드·산출물을 검증합니다. `contents: read` 권한으로 검사하며 사이트를 배포하지 않습니다.
- `.github/workflows/pages.yml`: **Deploy GitHub Pages** 워크플로입니다. `workflow_dispatch`로만 실행하므로 초안 커밋을 push해도 사이트는 공개·갱신되지 않습니다. 수동 실행에서도 검증을 거친 빌드 결과를 게시합니다.

강의를 수정한 뒤에는 다음 순서로 갱신합니다.

1. 로컬에서 원고를 수정하고 **파일 저장 완료**를 확인한 뒤 위의 테스트·콘텐츠 검사·빌드·산출물 검사를 실행합니다. Pages나 4188 미리보기에서 수정했다면 먼저 JSON을 로컬 원본에 반영합니다.
2. 변경 파일을 검토해 공개 저장소에 커밋·push합니다. 이 단계만으로 사이트가 자동 갱신되지는 않습니다.
3. [Actions → Deploy GitHub Pages](https://github.com/is2js/dolbeom-coding-notes/actions/workflows/pages.yml)의 **Run workflow**에서 게시할 검증된 브랜치를 선택하고 실행합니다. 저장소 쓰기 권한과 Pages 환경의 배포 허용 설정이 필요합니다. [수동 실행 공식 안내](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)를 참고하세요.
4. 실행이 성공하면 [강의 주소](https://is2js.github.io/dolbeom-coding-notes/)에서 강의 진입·시연·편집기·JSON 다운로드를 확인합니다. 이후 갱신할 때도 검증·push 후 **Run workflow**를 다시 실행합니다.

Pages 설정을 확인하거나 변경할 때는 **Settings → Pages → Build and deployment → Source**의 **GitHub Actions** 항목을 봅니다. [게시 소스 설정 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 참고하세요. 수동 워크플로 파일은 저장소의 기본 브랜치에 유지합니다.

배포 워크플로는 `actions/configure-pages`의 `base_path`를 `PAGES_BASE_PATH`로 빌드에 전달하고, 값이 비어 있으면 `/`를 사용합니다. 따라서 프로젝트 Pages의 `/저장소이름/` 경로와 사용자·조직 Pages 또는 연결 도메인의 루트 경로를 Pages 설정에 맞춰 처리합니다. 저장소 이름을 소스에 고정하지 않습니다. 로컬 빌드의 기본 경로는 `./`이며 개발 서버와 미리보기 포트는 각각 5188과 4188입니다.

Pages 배포 작업은 `pages: write`, `id-token: write` 권한과 `github-pages` 환경을 사용합니다. 워크플로 구성은 [GitHub Pages 사용자 지정 워크플로 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 따릅니다.

## 데이터와 구현

- Alpine.js 3.14.9, Tailwind CSS 3.4.17, Vite. 설치 버전은 lockfile로 고정합니다.
- 강의 데이터의 기준 파일은 **`public/data/course.json`**입니다. `content-parts/`는 최초 원고를 보존한 로컬 제작 자료이며 저장소 업로드와 배포에서 제외합니다. 현재 강의를 수정할 원본으로 사용하지 않습니다.
- 강의 ID는 기본 순서대로 `terminal`, `git`, `github`, `markdown`, `ide`, `web`, `templates`입니다. 강의 순서를 바꿔도 ID는 유지하고 표시 번호만 다시 붙입니다. 이전 `tools` 주소는 IDE로, `frontend`·`codex` 주소는 템플릿으로 연결합니다.
- 세부절의 장면은 `src/section-art-tools.js`, `src/section-art-web.js`에 있으며 `src/section-scenes.js`가 안정적인 절 ID로 연결합니다. 사용자가 새로 만든 절에 장면이 없으면 주제 기본 그림을 사용합니다.
- 주제 시작·정리의 중앙 입체 그림은 `src/illustrations/<강의 ID>.svg`의 주제별 장면입니다. 터미널 작업대, Git 분기·병합, GitHub 원격 협업, 마크다운 문서, IDE 편집 공간, 브라우저·서버, 템플릿 조립을 각각 다른 형태로 보여 줍니다. 제목이나 순서를 편집해도 같은 주제 ID의 그림을 유지합니다.
- 그림은 명령 입력·커밋 이동·문서 변환·요청과 응답처럼 주제에 맞는 일부 요소가 천천히 변합니다. 그림 아래 **움직임 멈춤 / 움직임 재생**으로 제어하며, 운영체제의 동작 줄이기 설정에서는 정지 화면을 표시합니다. 탭이 숨겨지거나 도구 시연으로 전환하면 애니메이션도 멈춥니다. 모션과 형상은 SVG, 공통 제어 스타일은 `src/illustrations.css`에서 수정합니다.
- 프론트엔드·백엔드와 서버 템플릿 절은 전용 개념 그림을 본문과 발표에서 보여 줍니다. **02 본문 → 본문·발표 개념 그림**에서 선택하며, 선택하지 않으면 기존 강의 그림을 사용합니다. 절의 `illustrationId`는 `web-architecture` 또는 `server-rendering`입니다.
- `schemaVersion: 1`의 전체 강의 JSON을 가져오거나 내보냅니다. 본편·보충 시간은 각 절의 `minutes`, `optional`로 계산합니다.
- 개발 서버의 `/__course-sync`가 로컬 파일 읽기·저장을 맡습니다. 저장 전에 파일 버전을 비교해 다른 변경이 있으면 충돌로 처리합니다. 이 기능은 개발 서버에만 있으며 빌드 결과와 미리보기에는 포함되지 않습니다.
- Markdown은 DOMPurify로 정제합니다. 가져온 코드를 평가하거나 실행하지 않습니다.
- 글꼴은 Pretendard, Barlow Semi Condensed, IBM Plex Mono를 외부 CDN에서 읽으며 연결되지 않으면 시스템 글꼴로 표시됩니다. 애플리케이션 코드와 스타일은 로컬 빌드에 포함됩니다.
- 디자인 참고: [Learn Arduino](https://learn-arduino-red.vercel.app/), 원본 디자인 [Dilum Sanjaya](https://x.com/DilumSanjaya). 로고·원본 3D 모델·원본 코드는 사용하지 않고 도구 지도와 아이콘을 새 SVG로 작성했습니다.

기존 PVP 프로젝트와 분리된 독립 프로젝트입니다. 강의 원본은 공개 저장소에서 관리하고 사이트는 위 수동 절차로 갱신합니다.
