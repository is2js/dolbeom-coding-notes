# OBS로 강의노트와 실습 창 무료 녹화

**OBS는 호스트 PC에서 실행하고, VM 또는 Sandbox 창을 영상 소스로 선택합니다.** 혼자 사전 녹화할 때 Zoom 결제·회의는 필요하지 않습니다. 가상 Windows 안에 OBS를 설치하지 않습니다. [OBS 공식 다운로드](https://obsproject.com/download)는 Windows 10·11을 지원합니다.

## 처음에는 두 장면만 만들기

기존 설정을 사용 중이라면 **프로필 → 새 프로필**, **장면 모음 → 새 장면 모음**에서 `돌범 강의`를 만들어 촬영 설정을 구분합니다.

| 장면 이름 | 영상 소스 | 설명할 내용 |
| --- | --- | --- |
| 강의노트 | **윈도우 캡처** → 전용 강의 브라우저 창 | 호스트의 로컬 원고·발표 모드 |
| 실습 | **윈도우 캡처** → Windows Sandbox 또는 Hyper-V 가상 컴퓨터 연결 창 | Terminal·Git·VS Code 설치와 실습 |

강의노트도 Sandbox 안에서 열면 **실습 장면 하나**로 시작해도 됩니다. 호스트 브라우저와 실습 환경을 오갈 때 두 장면으로 나눕니다. VM/Sandbox 창 안에서 앱을 바꾸면 같은 캡처 소스에 계속 보입니다.

### 필요한 부분만 남기기

1. 장면 선택 → **소스의 + → 윈도우 캡처** → 실제 창을 선택합니다. 처음에는 앱을 최소화하지 않습니다.
2. 가능한 경우 **클라이언트 영역(Client Area)**을 켭니다. Hyper-V 도구 모음이나 브라우저 북마크처럼 창 안에 남는 요소는 직접 자릅니다.
3. 미리보기의 소스를 선택하고 **Alt를 누른 채 테두리를 드래그**해 상하좌우를 자릅니다. 숫자로 조절하려면 우클릭 → **변환 → 변환 편집(Ctrl+E)**의 자르기 값을 사용합니다.
4. **Ctrl+F**로 화면에 맞추고 원본 비율을 유지합니다. 자른 뒤 소스의 **잠금**을 켜서 실수로 움직이지 않게 합니다. 캡처할 창 크기를 고정하고 코드 글자를 키웁니다.

윈도우 캡처는 다른 창이 앞에 있어도 선택한 창만 캡처합니다. **다만 Hyper-V·Sandbox 창에서 실제로 정상 캡처되는지는 확인이 필요합니다.** 검은 화면이면 소스 속성의 캡처 방식을 Automatic, Windows 10 방식, BitBlt로 바꾸며 시험합니다. 해결되지 않을 때는 강의 전용 화면을 **디스플레이 캡처 + 영역 자르기**로 잡습니다. 이 경우 그 영역에 뜬 다른 창과 알림도 녹화됩니다. [윈도우 캡처](https://obsproject.com/kb/window-capture-sources) · [소스와 영역 자르기](https://obsproject.com/kb/sources-guide)

## 영상·음성 시작 설정

다음은 코드 설명용 시작값입니다. 실제 녹화 결과를 보고 글자 크기와 화질을 조정합니다.

| 위치 | 시작값 |
| --- | --- |
| 설정 → 비디오 | 기본 캔버스·출력 1920×1080, 30fps. 원본 화면 비율을 유지하고 늘려 찌그러뜨리지 않기 |
| 설정 → 출력 → 출력 모드 | 간편(Simple) |
| 녹화 품질 | 높은 품질, 중간 파일 크기(High Quality, Medium File Size) |
| 인코더 | 실제 선택 목록에 있으면 하드웨어 NVIDIA NVENC H.264 |
| 녹화 형식 | MKV |
| 녹화 경로 | **호스트 PC 또는 외장 SSD의 촬영 폴더** — Sandbox/VM 내부에 저장하지 않기 |
| 설정 → 오디오 | 실제 마이크 한 개 지정. 설명만 녹음하면 데스크톱 오디오 사용 안 함 |

현재 GTX 1080 Ti는 NVENC를 사용할 수 있는 세대입니다. 설치된 드라이버와 OBS에서 사용 가능한지 확인하고, 표시되지 않으면 자동 구성 마법사나 사용 가능한 인코더로 시험합니다. [하드웨어 인코딩](https://obsproject.com/kb/hardware-encoding)

같은 마이크를 **전역 Mic/Aux**와 **오디오 입력 캡처 소스**에 중복 지정하지 않습니다. 말할 때 오디오 믹서의 미터가 움직이는지 확인합니다. 앱 소리도 필요하면 지원되는 앱 오디오 캡처를 사용하고, 같은 소리를 데스크톱 오디오와 중복 녹음하지 않습니다. 앱 소리 캡처가 안 되면 데스크톱 오디오만 사용하고 불필요한 알림 소리를 끕니다. 헤드폰을 쓰면 스피커 소리가 마이크로 다시 들어가는 일을 줄일 수 있습니다. [오디오 소스](https://obsproject.com/kb/audio-sources) · [앱 오디오 캡처](https://obsproject.com/kb/application-audio-capture-guide)

마이크는 **호스트 OBS**가 녹음합니다. 준비된 `lecture-sandbox.wsb`에서 Sandbox 마이크 입력을 꺼 두어도 호스트 OBS의 마이크 녹음은 별도로 동작합니다.

## 매번 촬영하는 순서

1. Sandbox 또는 VM을 열고 필요한 앱을 준비합니다. OBS에서 캡처 대상 창과 잘린 영역을 확인합니다.
2. **설정 → 단축키**에서 녹화 시작·정지와 `강의노트/실습` 장면 전환을 서로 다른 키로 지정합니다. 먼저 OBS가 보이는 상태에서 시험하고, VM에 포커스가 있을 때도 키가 호스트에 전달되는지 확인합니다. 전달되지 않으면 VM 밖에서 OBS를 조작합니다.
3. **60~90초 시험 녹화**로 설명 → Terminal 입력 → VS Code → 노트 복귀를 진행합니다. 녹화를 멈추고 파일을 재생해 목소리·작은 코드·마우스·장면 전환을 확인합니다. [OBS 시작 안내](https://obsproject.com/kb/quick-start-guide)
4. 본 촬영은 **5~10분짜리 절 단위**로 나눕니다. 다시 찍기 쉽고, 저장 공간과 파일 이상도 중간에 확인할 수 있습니다.
5. 녹화 후 필요하면 **파일 → 녹화 리먹스(Remux Recordings)**에서 MKV를 MP4로 바꿉니다. 리먹스는 재인코딩 없이 컨테이너를 바꾸는 작업입니다. MP4가 정상 재생되는지 확인하고 파일을 보관합니다. [녹화·리먹스 안내](https://obsproject.com/kb/standard-recording-output-guide) · [영상 형식](https://obsproject.com/kb/audio-video-formats-guide)
6. 필요한 실습 결과가 호스트에 저장되었는지 확인하고 Sandbox를 닫거나 VM을 복원합니다. 호스트에 저장한 녹화 파일은 유지됩니다.

## C: 여유 23GB에서 주의할 용량

OBS 파일은 **로컬 디스크에 쌓입니다.** Sandbox가 가볍더라도 앱 다운로드·임시 파일·녹화 파일이 공간을 함께 사용합니다. `High Quality`는 가변 용량이므로 **대표적인 1분 시험 파일 크기 × 예상 촬영 분량(분)**으로 먼저 예상합니다. 재촬영분과 MKV·MP4가 동시에 존재하는 공간도 더합니다. 예를 들어 고정 8Mb/s로 녹화하면 영상 데이터만 3시간 약 10.8GB이며, 음성·컨테이너 용량은 별도입니다. 위 간편 모드가 이 용량을 보장한다는 뜻은 아닙니다.

현재 공간에서 3시간을 한 번에 녹화하기보다 짧게 촬영하고, 완료 파일을 충분한 공간이 있는 다른 드라이브로 옮겨 관리하는 편이 낫습니다. C:를 정리하지 않아도 외장 SSD에 녹화할 수 있습니다.

| 선택 | 장점 | 준비할 점 |
| --- | --- | --- |
| **OBS 무료 로컬 녹화** | 영역 자르기·장면 전환·마이크 설정을 직접 조절, 회의 없이 녹화 | 호스트 저장 공간·파일 보관·시험 녹화 |
| **Zoom 유료 클라우드 녹화** | 회의와 녹화를 함께 진행, 클라우드에서 처리·보관 | 유료 라이선스·업로드·다운로드·클라우드 저장 한도 |

이 문서는 공식 문서를 바탕으로 한 준비 안내입니다. 현재 PC의 BIOS 가상화가 비활성으로 표시되어 Sandbox/VM 창의 실제 캡처와 설치는 아직 검증하지 못했습니다. 기존 OBS 설정은 변경하지 않았습니다.
